给 B（组长 + 前端）的任务说明
================================

你是项目组长，同时负责前端。前端活你已经干完了（四赛道、演示模式、文档整理），
现在你的核心角色是「发令 + 验收」：把脏活分出去（后端给 A、文档给 C、改联调给我），
你不用自己埋头写代码。

下面是你自己的任务清单，分「远程现在」和「回电脑后」两摞。


一、你已经完成的事（不用再管）
-----------------------------------
- 前端网页：四赛道（编程/论文/自律/日常闲聊）、多会话、深色模式、快捷键、导出、思考路径图、分享卡片等，全部做好并推上 git。
- 团队文档：整理进「协作文档」文件夹（01~04），已推 git；给 AI 看的 00 和 AGENTS.md 留本地不公开。
- 本地预览服：http://localhost:5500（python -m http.server 5500 起，偶尔会挂，挂了重启即可）。


二、远程现在就能做（3 件）
-----------------------------------
1. 发 A 话术——催他把后端 push 到 GitHub，并提醒他 push 前先 git pull（拉到你刚推的文档，免冲突）：
   > 哥，后端整好就 push 一下 main 吧，咱这项目不用打包编译。push 前先 git pull 拉一下我刚推的文档。
   > 另外 .env 的 CORS_ORIGINS 记得加 http://127.0.0.1:5500（前端端口），不然联调跨域报错。

2. 发 C 话术——让她看 03 用演示模式开干（不依赖后端）：
   > 妹，GitHub 上「协作文档」文件夹里看 03_给C的任务说明，照着写路演文档和测试清单。
   > 演示模式断网也能跑，不用等 A。拿不准发群里。

3. 关掉 WorkBuddy 里那个「邀请未通过后续步骤」任务（队友不用 WorkBuddy 协作，别让它占心思）。


三、等队友时你只盯两件事
-----------------------------------
4. A 推了没 → 推了就喊我（AI）帮你联调。
5. C 动没动 → 一天没动静再催一句。


四、回电脑后（喊我，脏活我干）
-----------------------------------
6. git pull 拿 A 的后端最新代码。
7. 我改前端 js/store.js，把 API_BASE 从演示地址换成 A 的真后端地址（http://127.0.0.1:8000 之类）。
8. 起 http://localhost:5500 测四赛道真模型通不通、跨域报不报错。
9. 通了 → 部署 EdgeOne Pages（注意：禁用 Vercel / Railway）。
10. 录最终路演视频 / 彩排。


五、验收标准（你说了算）
-----------------------------------
- 四个赛道都能走通「只提问不回答」的苏格拉底式反问，阶段推进正常。
- 前端连真后端无跨域报错（CORS 含 5500）。
- 部署后网址能打开、手机能看。
- C 的路演文档 + 测试视频齐活。


六、卡点怎么升級
-----------------------------------
- A 一直不推：再催，或问清他是卡环境还是卡代码，需要我写后端请直接说。
- C 不动：发 03 原文 + 鼓励，演示模式就能做，门槛很低。
- 联调报错：把报错截图发我，我盯着改 store.js / 让 A 查后端。


七、给你的 AI（WorkBuddy）使用规矩
-----------------------------------
