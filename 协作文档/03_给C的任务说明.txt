苏格拉底项目 · 成员 C 任务说明（手把手版）
=========================================
你是成员 C，负责「文档 + 测试 + 演示视频」——也就是路演时评委手里那套材料，
和给用户/测试同学看的操作指引。你不用写代码，这是你的主场。

先说一句大实话：你可能觉得「后端还没接真模型，我们做不好，我没法做」。
其实不是。下面「一」会讲清楚：现在已经有东西能写、能录了。

------------------------------------------------------------
零、你总共要交三样东西
------------------------------------------------------------
1. 路演文档 / PPT 文案（项目是啥、亮点、怎么用）
2. 测试清单（要测哪些功能、怎么算通过）
3. 演示视频（录一段产品怎么用，路演现场放）

------------------------------------------------------------
一、先搞清：项目现在到底做成啥样了（给你信心）
------------------------------------------------------------
前端（界面）已经做完，而且很完整。即使后端现在是「演示模式」（没接真模型），
下面这些都能正常演示、能录视频：

- 4 个赛道：编程排错 / 论文写作 / 自律习惯 / 日常闲聊
- 多会话：每个赛道能建很多条独立对话，左栏点开分类才显示
- 对话自动总结标题（不用你手命名）
- 右侧「思考路径图」：导师每问一个问题就长一个节点，点节点能跳回对应聊天
- 对话导出（存成 Markdown）、分享卡片（生成一张好看的图）
- 深色模式、键盘快捷键（Enter 发送）、复制单条、首次引导
- 最关键：演示模式下，你发一条消息，它也会一个字一个字反问你，
  右边的路径图会实时生长——评委看的就是这个「苏格拉底式只问不答」的机制，
  不是答案有多聪明。

所以：你录视频、写文档，现在就能动手，不靠 A 的真模型。

------------------------------------------------------------
二、你现在就能做的（不等 A）
------------------------------------------------------------
（一）路演文档 / PPT 文案
   直接用下面这些「已确定的事实」写，不用瞎编：

   项目名：苏格拉底式多赛道导师（暂定，可改）
   一句话：一个只提问、不回答的 AI 导师，用苏格拉底式引导你自己想明白。
   解决啥痛点：学生一遇问题就等答案，不动脑；这个产品逼你思考。
   四个赛道：编程排错 / 论文写作 / 自律习惯 / 日常闲聊
   三个亮点（写进 PPT）：
     1. 只问不答：符合教育理念，不是「抄答案工具」
     2. 思考路径图：把「被引导的过程」可视化，评委一眼看懂价值
     3. 断网也能演示：没模型、没网也能跑完整流程，路演现场稳
   技术栈（简单提）：前端原生 HTML/CSS/JS，后端 FastAPI + DeepSeek，SSE 流式。

   交付：一份 Markdown 或 Word（你习惯啥用啥），结构建议：
     封面 → 痛点 → 我们的方案 → 核心功能截图 → 创新点 → 应用前景 → 团队分工。

（二）测试清单
   列出要测的功能和「怎么算通过」，给 A、B 和你自己用。样例：
     - 发消息能收到逐字回复（演示模式也算过）
     - 四个赛道都能切、都能对话
     - 每条对话标题能自动生成
     - 导出能下载 .md；分享能出图
     - 深色模式切换正常
     - 刷新后对话不丢
     - 边界：空消息不发、连点发送不崩
   交付：一张表（Excel/在线表格都行），列「功能 / 操作步骤 / 预期结果 / 是否通过」。

------------------------------------------------------------
三、等 A 后端联调好后，你再做的
------------------------------------------------------------
（一）录真演示视频（建议 1~2 分钟）
   联调好后（A 的 Key 接上、B 的前端连上），挑一个赛道录一段真实对话。
   脚本建议：
     0:00 打开页面，点进「编程排错」
     0:10 发一条真实报错（比如「Python 循环死循环」）
     0:20 看导师逐字反问，右边路径图长出节点
     0:40 展示「思考路径图」点节点跳转
     0:55 点「导出」说明能带走复盘
   没联调好也别等：用演示模式先录一版，联调后再补真模型版。

------------------------------------------------------------
四、你卡住时的破法
------------------------------------------------------------
- 「不知道写啥」→ 用「一、二」里给的事实当骨架，先凑出初稿，再润色。
- 「没真模型录不了视频」→ 演示模式就能录（见一），先录一版占位。
- 「怕写错技术细节」→ 涉及后端/接口的细节问 A；涉及界面问 B；别自己猜。
- 「PPT 不会排版」→ 先用纯文字把文案写出来，排版最后弄，或让 B 美化。

------------------------------------------------------------
五、建议你按这个节奏
------------------------------------------------------------
第 1 天：写测试清单（二·二）+ 路演文档初稿（二·一）
第 2 天：用演示模式录一版演示视频占位
之后：等 A 联调 → 补真模型视频 + 文档定稿

有任何一步拿不准，把问题发群里，A/B 帮你盯。你这块不依赖写代码，是最稳的一环。
