## 1. 项目概述

**一句话定位**：一款基于大模型的 Web 应用，用"只提问不回答"的苏格拉底式对话，引导用户自主思考，覆盖**编程排错、论文写作、自律习惯**三个赛道；每个赛道进度独立保存，切换不丢失。

**我们要解决的痛点**：新手遇问题第一反应是向 AI 要答案，拿到答案能力却没提升。**我们的反直觉解法**：AI 当苏格拉底式导师，只提问、不给答案，用递进提问引导用户自己发现问题、得出结论。

**三个赛道**：

| 赛道 | 引导逻辑 | 高光功能 |
|---|---|---|
| 编程排错（programming） | 定位错误 → 分析原因 → 给出方案 | highlight.js 代码高亮 + Judge0 真跑 |
| 论文写作（thesis） | 明确立场 → 寻找论据 → 搭建框架 | 论点卡片 |
| 自律习惯（habit） | 拆解目标 → 预设障碍 → 制定策略 | If-Then 策略表 |

**核心创新点**：① 交互反直觉（比"谁更能忍住不回答"）；② 多赛道状态机可插拔（Prompt 与 Stage 解耦）；③ 引导进度可视化；④ 三赛道三套引导策略（收敛/发散/心理博弈）。

## 4. 接口与约定（前后端对接宪法）

**由成员 B（组长）主笔并定死**（初稿见配套 `接口与约定.md`），要点（v1.1 已修订）：

- `POST /chat`，请求体 `{message, track, user_id}`，`history` **可选**（后端以数据库为准）；**SSE 流式**响应。
- **前端用 `fetch` + `getReader()` 读流，不用 `EventSource`**（EventSource 仅支持 GET）。
- 新增 `GET /session?user_id=&track=`：前端加载/切赛道时取回 `stage`+`history`。
- `track` 枚举：`programming` / `thesis` / `habit`。
- SSE 事件：`token`（流式字）、`stage`（阶段推进）、`tool`（Judge0 结果，含 stdout/stderr）、`done`、`error`。
- 错误码：400 / 429（可选 `retry_after`）/ 500。

**任何一侧改接口，必须先改 `接口与约定.md` 并经三人确认，再写代码。**

## 6. 协同工作机制（三条铁律 + 工作流）

### 铁律一：B（组长）主笔《接口与约定.md》，对接定死
前后端不各自臆测字段。**Day 1–2 B 产出约定文档，A/C 确认后，双方按文档并行开发，互不阻塞。**

### 铁律二：统一骨架先行，AI 在约束内生成
Day 1 三人一起搭好 §3 的目录结构与空文件；AI 生成代码时严格遵循骨架与 `接口与约定.md`，不擅自改结构、不加未约定依赖。

### 铁律三：共享 Git 仓库 + 小步提交
- **仓库由组长 B 在第 0 天建好并邀请 A、C 为协作者**（操作见上方"GitHub 协作前置"）；A、C 接受邀请后即可提交。
- **主分支 `main` 受保护**，开发走 `feature/xxx` 分支，PR 合并。
- **小步提交**：每完成一个子任务即 commit（如 "feat: A 完成 /chat 基础接口"），**禁止最后一次性 push**——评审要求"体现真实开发过程"。
- commit message 规范：`feat/fix/docs/refactor: 简短说明`。
- B（组长）负责审核 PR、每日合并冲突、保持 main 可运行。

### 工作流：Prompt-First（写码前先把提示词发给 AI）
每个任务卡先附 Prompt（角色/目标/约束/输入输出/验收/反例）→ **先发 AI 拿"方案+文件结构+函数签名"，人审确认** → 再让 AI 写码 → 跑通 → 小步 commit。

### 每日"能跑通检查"（17:00）
A 起后端、B 起前端、C 用真浏览器走 happy path；红色项当天修。PR 合并前必须 C 本地跑通才算 Done（Runnable Gate）。

打开 `http://127.0.0.1:3000`，输入"我的代码报错了"，确认 AI 只提问不回答；测试切赛道进度不丢。报错复制给对应成员修。

### 7.2 部署上线（⚠️ 必须国内可达）

> **最大坑**：Vercel/Railway 国内访问不稳，评委打不开 = 零分。**务必换国内平台，并准备兜底。**

**推荐组合（国内可达）**：
- **前端**：腾讯云 **EdgeOne Pages**（静态托管，体验类似 Vercel，国内访问快）/ 或阿里云 OSS + CDN。
- **后端**：阿里云 **函数计算 FC**（Serverless，按量计费很便宜）/ 或**轻量应用服务器 ECS**（最省心，一台小规格即可）。

**步骤**：
1. A：推 `backend` 到 GitHub → 连国内云平台（FC/ ECS）→ 配 `DEEPSEEK_API_KEY` → 获公网地址。
2. B：推 `frontend` 到 GitHub → 连 EdgeOne Pages → 获公网地址。
3. B：把请求地址改为 A 的后端公网地址。
4. A：改 CORS `allow_origins` 为前端域名。
5. C：打开公网地址全功能自测。

> ⚠️ **兜底（必做）**：① 第 3 周末就部署测一次，别等到第 4 周；② 预录 5–8 分钟演示视频（任务6）；③ README 写清本地一键运行，万一线上挂了评委能本地跑。

### 7.3 一键自检（smoke.ps1，Windows）

仓库根目录放 `smoke.ps1`，本地/部署前跑：
```powershell
# smoke.ps1 —— 右键"使用 PowerShell 运行"，或：powershell -ExecutionPolicy Bypass -File smoke.ps1
function Check($name,$uri){ try { Invoke-WebRequest -Uri $uri -UseBasicParsing -TimeoutSec 5 -ErrorAction Stop | Out-Null; Write-Host "$name OK" } catch { Write-Host "$name 未启动/不可达" } }
Write-Host "==> 检查后端存活";   Check "后端" "http://127.0.0.1:8000/docs"
Write-Host "==> 检查前端可达";   Check "前端" "http://127.0.0.1:3000"
Write-Host "==> 检查 /chat (POST)"; try {
  $r = Invoke-WebRequest -Uri "http://127.0.0.1:8000/chat" -Method POST -ContentType 'application/json' `
        -Body '{"message":"你好","history":[],"track":"programming","user_id":"smoke-test"}' -UseBasicParsing -TimeoutSec 10
  Write-Host "/chat OK ($(($r.Content).Length) 字节)"
} catch { Write-Host "/chat 异常: $_" }
```

**手动替代（不想用脚本）**：浏览器分别打开 `http://127.0.0.1:8000/docs` 和 `http://127.0.0.1:3000`，都能开 = 通过。

### 7.4 常见问题
- **Redis 不用装**：状态用 sqlite3 单文件或内存字典，无需任何额外服务。
- **Key 泄露**：`.env` 已在 `.gitignore`，提交前 C 抽查。
- **前端必须用服务起**：`python -m http.server` 或 `npx serve，不能直接双击 html（ES Module 会跨域失败）。
- **SSE 用 fetch 读**：浏览器 `EventSource` 只支持 GET，本项目是 POST，必须用 `fetch` + `getReader()`，否则联调必崩。
- **Judge0 国内不通**：先在 A 本地测；调不通就降级为返回"模拟运行结果"，不影响主流程。
