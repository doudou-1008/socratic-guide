# 接口与约定（Interface & Contract）

> **主笔**：成员 B（组长）　**确认**：成员 A、成员 C　**状态**：v1.1（吸收联调评审修订）
> **作用**：本项目前后端对接的"宪法"。任何一侧改动接口，必须先改本文档并经三人确认，再写代码。

### v1.1 修订要点
- ⚠️ **前端必须用 `fetch` 读 SSE 流，不能用 `EventSource`**（EventSource 仅支持 GET，不支持 POST）。
- `history` 改为**可选**，后端一律以数据库为准；新增 `GET /session` 供前端取回历史。
- 部署地址改为国内可达平台（详见协作手册 §2）。

## 1. 基础约定

| 项 | 约定 |
|---|---|
| 后端根地址（本地） | `http://127.0.0.1:8000` |
| 后端根地址（部署） | **国内可达平台**（阿里云函数计算 FC / 轻量应用服务器 ECS，详见协作手册 §7.2） |
| 接口协议 | HTTP + **SSE（Server-Sent Events）流式** |
| 请求 Content-Type | `application/json` |
| 字符编码 | UTF-8 |
| 用户标识 | 前端首次访问生成 `user_id`（UUID v4），localStorage 持久化；每次请求携带 |
| 认证 | 内测阶段无登录；`user_id` 即会话标识 |
| 历史来源 | **以后端数据库为准**，前端不负责存取（见 §2.1 / §2.3） |

## 2. 核心接口

### 2.1 `POST /chat`（主对话接口）

**请求体（JSON）**

```json
{
  "message": "我的 Python 代码报错了 IndexError: list index out of range",
  "history": [],
  "track": "programming",
  "user_id": "a1b2c3d4-1234-5678-90ab-cdef12345678"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `message` | string | 是 | 本次用户消息 |
| `history` | array | **否** | **可选**。后端以数据库为准；前端可不传，由后端从库里取历史 |
| `track` | string | 是 | 赛道枚举，见 §3 |
| `user_id` | string | 是 | 用户 UUID |

### 2.2 响应：`POST /chat` 返回 SSE 事件流

`Content-Type: text/event-stream`，每条事件格式 `data: <JSON>\n\n`。

| 事件 `type` | 字段 | 含义 | 前端动作 |
|---|---|---|---|
| `token` | `content: string` | 流式输出的一个字/词 | 追加到当前 AI 气泡 |
| `stage` | `stage: number`, `label: string` | 引导进入下一阶段 | 点亮进度条对应节点（见 §3） |
| `tool` | `name: string`, `stdout: string`, `stderr: string` | 工具调用结果（如 Judge0 运行结果） | 在代码高亮区展示运行结果 |
| `done` | — | 本轮结束 | 关闭流式、刷新本地状态 |
| `error` | `message: string` | 出错 | 显示错误提示 |

**⚠️ 前端读取方式（铁律）**：浏览器原生 `EventSource` **只能发 GET，不支持 POST**。本项目 `/chat` 是 POST，因此：
> **前端必须用 `fetch` + `response.body.getReader()` 手动读流**，不要用 `EventSource`。示例：
```js
const res = await fetch('/chat', {method:'POST', headers:{'Content-Type':'application/json'}, body: JSON.stringify(payload)});
const reader = res.body.getReader(); const dec = new TextDecoder();
while(true){ const {done,value}=await reader.read(); if(done) break;
  // 解析 data: {...}\n\n 片段，按 type 处理 token/stage/tool/done }
```

**示例流**：
```
data: {"type":"token","content":"别"}
data: {"type":"token","content":"急，"}
data: {"type":"tool","name":"judge0","stdout":"TypeError: ...","stderr":""}
data: {"type":"stage","stage":2,"label":"分析原因"}
data: {"type":"done"}
```

### 2.3 `GET /session`（取回历史，新增）

前端在**页面加载**和**切换赛道**时调用，从后端拿回该用户的阶段与历史（因为历史以数据库为准）。

**请求**：`GET /session?user_id=xxx&track=programming`

**响应（JSON）**：
```json
{ "stage": 2, "history": [ {"role":"user","content":"..."}, {"role":"assistant","content":"..."} ] }
```

### 2.4 错误码

| HTTP 码 | 含义 | 前端处理 |
|---|---|---|
| 400 | 参数缺失/非法（如 `track` 不在枚举） | 提示"请求格式错误" |
| 429 | 调用超限（DeepSeek/Judge0） | 提示"稍后再试"，可选读 `retry_after` 字段 |
| 500 | 后端异常 | 提示"服务异常"，可重试 |

## 3. 赛道（track）枚举与阶段（stage）定义

| `track` | 含义 | 阶段节点（stage 从 1 递增） |
|---|---|---|
| `programming` | 编程排错导师 | 1 定位错误 → 2 分析原因 → 3 给出方案 |
| `thesis` | 论文写作导师 | 1 明确立场 → 2 寻找论据 → 3 搭建框架 |
| `habit` | 自律习惯教练 | 1 拆解目标 → 2 预设障碍 → 3 制定策略 |

- 每个 `user_id + track` 有**独立**的 `history` 与 `stage`，切换赛道互不干扰。
- 阶段推进由**后端**判断，通过 `stage` 事件通知前端，前端不自行推断。

## 4. 数据模型

### 4.1 会话状态（后端持久化，SQLite 单文件 `state.db`）

```
表 session(
  user_id   TEXT,
  track     TEXT,
  stage     INTEGER,
  history   TEXT,   -- JSON 数组序列化（后端写入，前端不写）
  updated_at TEXT,
  PRIMARY KEY(user_id, track)
)
```

> 轻量备选：内存字典 + 定时 dump 到 `state.json`；演示保持服务不重启即可。
> **历史以本表为准**，前端通过 `GET /session` 读取，不在自己侧维护权威历史。

### 4.2 前端状态（原生 `store` 对象，发布订阅，仅存"界面态"）

```js
// store.js —— 等价于 Zustand，但零框架。只存 UI 态，历史从后端拉
const store = {
  state: { userId, track, stage:{}, streaming:false, messages:[] },
  listeners: [],
  subscribe(fn){ this.listeners.push(fn) },
  set(patch){ Object.assign(this.state, patch); this.listeners.forEach(f=>f(this.state)) }
}
// 切赛道/刷新页面时：const s = await (await fetch(`/session?user_id=${id}&track=${t}`)).json(); store.set({stage:{[t]:s.stage}, messages:s.history})
```

### 4.3 知识库 `knowledge.json`（RAG 轻量检索源）

```json
{
  "programming": [
    {"keywords":["IndexError","list","索引"], "hint":"引导用户先确认列表实际长度与访问下标"},
    {"keywords":["TypeError","NoneType"], "hint":"引导用户检查变量是否在某分支未被赋值"}
  ],
  "thesis": [ {"keywords":["开头","立场"], "hint":"先帮用户明确核心立场再谈结构"} ],
  "habit":  [ {"keywords":["坚持","放弃"], "hint":"引导用户预设障碍并制定 If-Then 微小替代"} ]
}
```
